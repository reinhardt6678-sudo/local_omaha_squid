# 🦑 奥马哈 · 鱿鱼局

本地运行的 PLO4（四张底牌、底池限注奥马哈）应用，与内置机器人对战，带「鱿鱼游戏」附加彩头玩法。
纯前端，不需要服务器，浏览器打开就能玩。

```bash
npm install
npm run dev      # 开发模式，浏览器打开 http://localhost:5173
npm run build    # 生产构建，产物在 dist/
npm test         # 运行测试
```

## 一键启动（Windows）

不想每次都开命令行的话，双击仓库根目录的 **`启动游戏.cmd`** 就能开打：它会自己找到 Node
（不需要配 PATH）、第一次运行时自动装依赖、然后起服务器并打开浏览器。关掉黑窗口即结束游戏。

想要桌面快捷方式，跑一次：

```bash
powershell -ExecutionPolicy Bypass -File scripts\create-shortcut.ps1
```

这会在桌面和开始菜单各放一个「奥马哈鱿鱼局」快捷方式（图标是现场画的：绿呢台面上一张扑克牌，
黑桃红心角标，牌面是鱿鱼），启动器本体装在
`%LOCALAPPDATA%\OmahaSquid\`，所以快捷方式跟当前分支无关，仓库里也不会多出未跟踪的文件。
**仓库换过位置、或者 `scripts\launch.ps1` 改过之后，重跑一次上面的命令即可。**

几个细节：

- 已经在跑的时候再点一次快捷方式，只会把浏览器标签重新打开，不会起第二个服务器。
- 没装 Node 的机器上会提示去 <https://nodejs.org> 装 LTS 版，而不是闪退。
- `scripts\launch.ps1 -Port 5199 -NoOpen` 可以换端口 / 不自动开浏览器。

## 鱿鱼游戏规则

- 每轮发 **N + 3** 条鱿鱼，N 为桌上人数（6 人桌 = 9 条）。
- 每手牌结束后，**赢家拿走 1 条**鱿鱼。
- **平分底池时本手不发鱿鱼**，累积到下一手：下一手赢家拿 2 条；再平分则拿 3 条，以此类推。
- 鱿鱼的价值：基础每条 **2BB**，持有 **3 / 5 / 7** 条时依次翻倍。

  | 持有条数 | 1~2 | 3~4 | 5~6 | 7+ |
  | --- | --- | --- | --- | --- |
  | 倍数 | ×1 | ×2 | ×4 | ×8 |

  收入 = 条数 × 2BB × 倍数

- **没拿到鱿鱼的人平摊支付**所有收入。

### 结算时机

两种情况会触发结算，然后重置鱿鱼数量开始新一轮：

1. **鱿鱼发完** —— 所有 N+3 条都发出去了。
2. **最后一人提前结束**（默认开启）—— 一旦场上只剩一名玩家还没有鱿鱼，本轮立即结束，
   由这名玩家独自支付当前场上所有鱿鱼的价值。

关闭「提前结束」后，牌局会一直打到鱿鱼发完；如果那时所有人都至少有 1 条，
则由持有数最少的那一档玩家平摊（保证结算永远是零和的）。

### 规则示例（对应代码里的测试用例）

6 人桌，一轮共 9 条鱿鱼。A 拿 4 条、B 拿 3 条、C 和 D 各 1 条，E 和 F 没拿到：

| 玩家 | 鱿鱼 | 倍数 | 金额 |
| --- | --- | --- | --- |
| A | 4 | ×2 | 4 × 2 × 2 = **+16BB** |
| B | 3 | ×2 | 3 × 2 × 2 = **+12BB** |
| C | 1 | ×1 | **+2BB** |
| D | 1 | ×1 | **+2BB** |
| E | 0 | — | **−16BB** |
| F | 0 | — | **−16BB** |

总计 32BB，由 E、F 两人平摊，每人 16BB。

### ⚠️ 单挑桌的注意事项

「提前结束」规则在 2 人桌会退化：第一手分出胜负后就只剩 1 人没有鱿鱼，本轮立刻结算。
实际效果是每手牌输家固定支付 2BB，鱿鱼的累积和翻倍机制完全用不上。
**单挑时建议在设置里关掉「提前结算」。** 应用在选择 2 人桌时会给出提示。

## 机器人

所有机器人共用**同一套基准策略**（`src/bots/policy.ts`），风格档案只是在几个旋钮上做偏移，
而不是各写一套互不相干的逻辑。

### 基准策略在做什么

真正的 PLO GTO 解无法在浏览器里实时求解（每人 4 张底牌，翻后 60 种组合），
所以基准策略是按博弈论原则构造的启发式：

- **翻前**：按位置划分范围百分位。手牌强度由 `src/bots/preflop.ts` 打分，
  综合对子价值、同花价值、顺子覆盖度和孤张惩罚，再用采样得到的百分位表换算成
  「这手牌排在前百分之几」。三条会被大幅折价（自己堵死了自己的出路），
  顺连结构权重很高（符合 PLO 里 JT98 双同花与 AAxx 同档次的实战认知）。
- **翻后**：用蒙特卡洛模拟估算胜率（`src/bots/equity.ts`），再结合：
  - **底池赔率** —— 跟注需要的胜率 = 跟注额 / (底池 + 跟注额)
  - **平衡诈唬比例** —— 下注 b、底池 p 时，诈唬占下注范围的 b/(p+2b)，
    这正是让对手的抓诈牌跟或弃都无所谓的平衡点
  - **人数修正** —— 人越多，价值下注和诈唬的门槛都越严
- **混合策略**：所有阈值都用平滑过渡（sigmoid）而不是硬边界，
  所以同一手牌在同样场景下不一定每次都打得一样 —— 这是 GTO 的核心特征之一。

界面右侧的「机器人思考」面板会实时显示每个决策的理由和各选项的概率分布。

### 机器人怎么算鱿鱼

只会算底池的机器人，在这个游戏里打的是错误的策略：赢下一手牌拿到的不只是底池，
还有「本轮不用买单」。`src/bots/squidValue.ts` 把这笔账折算成筹码：

- **边际价值** —— 直接调用真正的结算函数算两次：「此刻收摊我拿多少」和
  「这手赢了鱿鱼之后收摊我拿多少」，两者之差就是这手牌在鱿鱼上值多少 BB。
  没有另写一套估值公式，所以结算规则怎么改，机器人的账就跟着怎么变。
- **紧迫度** —— 本轮才刚开始的话，这手不赢下手还能赢，这笔钱不该全额计入；
  鱿鱼快发完时就没有下次了。开启「提前结算」且只剩两人没鱿鱼时紧迫度直接拉满：
  谁先拿到，另一个就要独自买单。
- **并进底池赔率** —— 跟注需要的胜率从 `跟注额 / (底池 + 跟注额)` 变成
  `跟注额 / (底池 + 跟注额 + 鱿鱼奖励)`。「把底池直接抢下来」也更值钱了，
  所以诈唬频率同步上调。翻前底池只有几个盲注，拿它当分母会把压力放大到离谱，
  改用「打完一手大致要投入多少」（6BB）作参照。

机器人思考面板会把这笔账显示出来，比如
`🦑 本轮剩 7/9 条，我 0 条：赢下这手在鱿鱼上值 3.0BB × 紧迫度 34% = 1.3BB`。

档案里的 `squidAwareness` 决定各风格有多重视这笔账，本身就是一种性格：
岩石（0.45）之所以是岩石，正是因为它算不清这笔账 —— 而它恰恰是被这个规则罚得最惨的。
在设置页可以整桌关掉，机器人就退回纯扑克策略。

同种子 2500 手对局的 A/B（`--blind-bots` 对照）显示，**7 种风格的入池率无一例外地上升**：

| 风格 | 鱿鱼意识 | VPIP（关） | VPIP（开） |
| --- | --- | --- | --- |
| GTO 基准 | 1.0 | 21.2% | 26.2% |
| 紧凶 | 0.95 | 15.5% | 17.6% |
| 松凶 | 1.15 | 34.4% | 37.7% |
| 紧弱岩石 | 0.45 | 11.0% | 12.4% |
| 松弱跟注站 | 0.5 | 60.3% | 63.8% |
| 疯子 | 1.25 | 45.1% | 49.9% |
| 跛入鱼 | 0.6 | 49.2% | 50.9% |

（单个种子的样本，绝对值会有波动，但七个档案方向一致。）

### 风格档案

| 档案 | VPIP | PFR | 特点 |
| --- | --- | --- | --- |
| GTO 基准 | ~23% | ~14% | 所有系数为 1.0，其他风格的偏移原点 |
| 紧凶 (TAG) | ~15% | ~11% | 入池少但打得凶 |
| 松凶 (LAG) | ~32% | ~25% | 范围宽、攻击性强、频繁 3bet |
| 紧弱岩石 | ~9% | ~5% | 只玩顶级牌，加注基本就是真牌 |
| 松弱跟注站 | ~65% | ~21% | 什么都想看翻牌，极难弃牌 |
| 疯子 | ~46% | ~38% | 超高频加注诈唬，几乎不看牌力 |
| 跛入鱼 | ~50% | ~12% | 爱跛入看翻牌，翻后被动 |

（VPIP/PFR 数据来自 `scripts/simulate.ts` 的模拟对局，关闭鱿鱼意识时测得，
多个随机种子间波动小于 1.5%。开启后各档案会更松，见上表。）

可调旋钮见 `src/bots/profiles.ts`：`openRange`、`threeBet`、`callRange`、`limpiness`、
`aggression`、`bluff`、`callDown`、`sizing`、`randomness`、`squidAwareness`。
想加新风格只要往数组里加一条即可。

## 数据统计

右侧「数据统计」面板分三个标签，随时能看清桌上每个人在干什么：

| 标签 | 指标 |
| --- | --- |
| 扑克 | 入池率 VPIP、翻前加注率 PFR、3bet 率、翻后激进指数 AF |
| 摊牌 | 看翻牌率、摊牌率 WTSD、摊牌胜率 W$SD、赢手率 |
| 鱿鱼 | 累计鱿鱼条数、买单轮数 / 总轮数、鱿鱼结算净额、总盈亏 |

下方是全员盈亏曲线（自己那条高亮）。**「鱿鱼BB」和「盈亏」这两列并排看最有意思** ——
一眼就知道某个人的输赢是牌打出来的，还是鱿鱼买单买出来的。

「买单轮数」是这个游戏里真正决定输赢的数字：决定你是否买单的不是赢了多少条鱿鱼，
而是本轮有没有至少赢下一手。

## 代码结构

```
src/
  engine/          纯粹的扑克规则，不依赖 React
    cards.ts       牌的表示、洗牌、可指定种子的随机数
    evaluator.ts   五张牌评分 + 奥马哈「必须 2 底牌 + 3 公共牌」的最优组合
    pots.ts        主池/边池切分与派彩
    table.ts       一手牌的状态机（下注轮、底池限注、全下、摊牌）
    squid.ts       鱿鱼规则与结算
  bots/
    preflop.ts     翻前手牌强度评分 + 百分位表
    equity.ts      蒙特卡洛胜率
    policy.ts      基准策略（翻前范围 / 底池赔率 / 平衡诈唬）
    squidValue.ts  鱿鱼压力：赢下这手在鱿鱼上额外值多少筹码
    profiles.ts    风格档案
  game/
    session.ts     把牌桌、鱿鱼、机器人接成完整对局循环
    store.ts       接到 React 的状态容器
  ui/              界面组件
scripts/
  calibrate.ts     采样生成翻前百分位表，并检查分数与实战胜率的相关性
  simulate.ts      机器人批量对战，统计 VPIP/PFR/买单次数等
```

`engine/` 和 `bots/` 完全不依赖界面，可以单独在 Node 里跑批量模拟 ——
界面里看到的和几万手模拟出来的是同一套逻辑。

### 辅助脚本

```bash
npx vite-node scripts/calibrate.ts              # 重新校准翻前百分位表
npx vite-node scripts/simulate.ts 3000           # 机器人互打 3000 手
npx vite-node scripts/simulate.ts 3000 --no-squid # 关闭鱿鱼，只看纯扑克
npx vite-node scripts/simulate.ts 3000 --blind-bots # 鱿鱼照常，但机器人不会算它
SEED=999 npx vite-node scripts/simulate.ts 3000   # 指定随机种子
```

## 关于胜率数据的说明

模拟脚本会输出各风格的 BB/100 win rate，但**这个数字在几千手的样本下毫无意义**：
PLO 本身方差极大，加上鱿鱼结算每约 10 手就产生一次 ~30BB 的强制转移，
换个随机种子排名就会完全颠倒（实测同样 2500 手，某个风格能从 +496BB/100 变成 −540BB/100）。

要分辨风格之间真实的胜率差距需要十万手以上的样本。
**VPIP / PFR / 买单次数这些高频指标才是稳定可信的**，也是验证机器人行为是否符合设计的正确依据。

一个由模拟数据支持的、关于鱿鱼玩法的观察：**这个规则结构性地惩罚紧手**。
决定你是否买单的不是赢了多少条鱿鱼，而是「本轮有没有至少赢下一手」。
紧弱岩石（赢手率 ~4%）在模拟中的买单次数是疯子（赢手率 ~22%）的 7 倍以上。
换句话说，鱿鱼局会推着大家把牌打得更松、更愿意进池 —— 这大概正是这个彩头玩法的设计意图。

## 测试

```bash
npm test
```

88 项测试，覆盖：

- 评牌器的所有牌型、大小比较、轮子顺子，以及奥马哈「必须用两张底牌」的约束
- 底池限注的下注上限（翻前最大开池 3.5BB、翻后满池）、大盲选择权、加注重开行动权
- 边池切分、未跟注下注的退还
- **300 手随机对局的筹码守恒**（总量不变、无负筹码、赢家确实是最强牌）
- 鱿鱼规则：翻倍档位、平分底池累积、提前结束、零和性、取整后仍精确零和
- 上面那个 6 人桌规则示例的完整数值
- 机器人在随机局面下只会给出合法动作，且策略概率分布归一
- 鱿鱼压力的边际价值算得对（含翻倍档位、平分累积、只剩两人没鱿鱼的决胜局），
  以及同一批牌下有压力时确实进池更多
- 200 手对局后所有统计指标的分子都不超过分母、鱿鱼结算轮数对得上，
  **且盈亏曲线的每一个采样点都是零和的**
